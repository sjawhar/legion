# A reflection census over a shared type is a cross-branch gate, and a forward merge is where it fires

Extends docs/solutions/legion/conflict-only-rebases-keep-the-diff-auditable.md.
That document's "`MERGEABLE` is not 'compatible'" names the symptom — the failing test is not in
your tree. This is the shape that produces it most reliably, and what each side owes.

- **Landing a test that enumerates a shared type by reflection makes every branch in flight that
  adds a member to that type fail, in a file none of them touches.** No conflict marks it, and a
  handshake about shared files does not cover it, because the file is not shared. Say in the
  test's own comment what a later member must do, and publish to the branches you know are
  editing that type, as you would for a file conflict.
- **Merging such a base: the census forces a product decision, not a conflict resolution.** "Live
  or refused" is a choice about what the mode does, so it belongs in the merge commit's message
  and in the pull request body with the other behaviour changes, not swallowed as merge noise.
- **A proof harness built from a generated SDK must be rebuilt at the merge head, and a break
  there is often the sibling's contract change.** Rebuild from the merged schema and attribute
  the break by name; a reader otherwise takes it for your branch's regression.

## Evidence

- sjawhar/legion#2529 and #2528 ran at the same time on `packages/envoy/infra/gcp`. Their two
  implementers agreed every shared-file resolution over Envoy before either pushed, down to one
  table row of the README. What broke was in `gcp/dispatch_cluster_only_test.go`, a file #2528
  created and #2529 had never seen: `TestDispatchEveryInputIsLiveOrRefusedUnderClusterOnly` failed
  at the clean merge with 53 inputs against 50 covered, naming `natsInCluster`, `natsReplicas` and
  `streamMaxBytes`. The text merge of that file was clean; the census was not.
- The decision the census forced — all three inputs configure Dispatch, so all three are refused
  under `clusterOnly` — is recorded in merge commit `54644c3d1fa0`'s message and in the pull
  request's forward-merge comment, beside the resolutions.
- #2528 also made thirteen `gcp:Dispatch` inputs optional. The throwaway consumer program of
  #2529's proof, generated by `pulumi package add` against the plugin, stopped compiling at the
  merge head until seven inputs were wrapped in `pulumi.StringRef` — #2528's breaking change,
  named as such in the proof rather than fixed in silence.
- This repository keeps a family of such censuses (`aws/seeds_test.go`,
  `gcp/clusteredhub_refusals_test.go`, `aws/natsservice_test.go`) and its own guidance recommends
  adding more, so the cost recurs rather than being one branch's bad luck.
