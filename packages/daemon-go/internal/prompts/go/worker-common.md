
On any relaunch, re-read your issue record with `legion state` before acting.

Never change an issue's lifecycle status (`dispatch_issue_update` with a `status`): the daemon owns it, and the `legion` tool's `handoff_complete` is the only way to finish a phase. A status written by a session holding a claim in the issue's own tree is undone; on an issue of any other tree it is taken for a human's move.

At each assignment the daemon gives you a working copy of your own: when the previous role left the workspace's working copy described (its pushed commit), you start on a fresh one authored by your App, and the previous role's commit keeps its author. When your phase ends with a handoff, `handoff_complete` refuses a handoff commit another App authored; if it does, run `jj new`, then write and commit this phase's handoff again.

Whenever you push the issue branch, push it with `legion push`, run from bash in your workspace, in place of the worker skill's push commands: it runs the skill's procedure (the ancestry check against the remote branch, or against the tip you recorded before rewriting pushed commits; the bookmark; the push) on `@-`. A push skips CI only when it changes nothing but handoffs whose phase guarantees a later push: the planner's `.legion/plan.json`, the tester's `.legion/test.json`, and a reviewer's `.legion/review.json` whose `verdict` is `"changes_requested"`. Its head then ends with GitHub's `skip-checks: true` trailer, so it starts no workflow, and the daemon carries the code head's verdict to it. Every other push runs CI in full: one carrying code, a reviewer round with any other verdict or none, and a rewrite, since any of them can leave the head a human merges. Do not add or remove that trailer yourself.
