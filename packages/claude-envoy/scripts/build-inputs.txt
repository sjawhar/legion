# Every git pathspec whose files can change the Claude Code plugin's build (dist/ and legion/,
# built by scripts/build.ts and checked by scripts/verify-build.sh).
#
# Format: one git pathspec per line, relative to the repository root. A line that is empty or
# starts with # is ignored. Nothing else is special: a pathspec line holds the pathspec alone, with
# no trailing comment.
#
# Who reads it:
# - a person, and release.yaml's $CLAUDE_ENVOY_VERSION_ARGS, which carries this list's package
#   and content paths by hand: the release's version is bumped from the commits since the newest
#   claude-envoy-v* tag that touch them, so a source missing from both is one no release
#   publishes a new version for. A path added or dropped here is owed the same change there.
#   The toolchain entries below (.bun-version, bunfig.toml, bun.lock, the root package.json, the
#   .gitattributes files and the .github paths) are not among them, as no plugin's version
#   arguments carry theirs: a lockfile or runner change alone releases nothing, and the next
#   source commit publishes whatever it built.
# - tests/build-inputs.test.ts, which runs the build and fails when a file the bundles or the
#   Legion plugin read is not matched: each bundle's sources, the manifest, tsconfig and license
#   files of each workspace package they reach, the lockfile, root manifest and patches that decide
#   what bun install puts in node_modules, and the skills and agents buildLegionPlugin reads. The
#   rest is listed by hand and no test checks it: .bun-version, bunfig.toml, the
#   .gitattributes files, scripts/third-party-notices.ts (and any other module build.ts imports
#   from outside the packages below), scripts/pi-plugin-prepack.sh and the three .github paths at
#   the end. A change that makes build.ts or verify-build.sh read a new file adds it here.
#
# The rule: whole package directories are listed and only known non-inputs are excluded, so a file
# nobody thought of counts as an input. That is the safe direction: a false "changed" costs one
# extra patch release, while a false "unchanged" leaves npm's newest release behind its inputs
# with nothing queued to catch it up.
#
# This file is inside packages/claude-envoy, listed below, so a change to the list is itself an
# input change.
