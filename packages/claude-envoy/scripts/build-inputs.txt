# Every git pathspec whose files can change main's Claude Code plugin build (dist/ and legion/,
# built by scripts/build.ts and checked by scripts/verify-build.sh).
#
# Format: one git pathspec per line, relative to the repository root. A line that is empty or
# starts with # is ignored. Nothing else is special: a pathspec line holds the pathspec alone, with
# no trailing comment.
#
# Who reads it:
# - .github/scripts/release-push.sh push-built, with git alone (the push job runs no dependency
#   code): `git show <base>:packages/claude-envoy/scripts/build-inputs.txt`, then
#   `git diff --no-renames --name-only <base> <tip> -- <pathspecs>` to decide whether main moved by
#   a build input since the base the build was made from.
# - tests/build-inputs.test.ts, which runs the build and fails when a file the bundles or the
#   Legion plugin read is not matched: each bundle's sources, the manifest, tsconfig and license
#   files of each workspace package they reach, the lockfile, root manifest and patches that decide
#   what bun install puts in node_modules, and the skills and agents buildLegionPlugin reads. The
#   rest is listed by hand and no test checks it: .bun-version, bunfig.toml, the .gitignore and
#   .gitattributes files, scripts/third-party-notices.ts (and any other module build.ts imports
#   from outside the packages below), scripts/pi-plugin-prepack.sh and the four .github paths at
#   the end. A change that makes build.ts, verify-build.sh or the workflow read a new file adds it
#   here. The same test holds .github/workflows/claude-envoy-rebuild.yaml's on.push.paths to the
#   files these pathspecs match, so a push that changes a build input starts a rebuild and one that
#   changes none starts nothing: a pathspec added here that matches a file of the repository is
#   owed a pattern there in the same change.
#
# The rule: whole package directories are listed and only known non-inputs are excluded, so a file
# nobody thought of counts as an input. That is the safe direction: a false "changed" costs one
# extra rebuild run, while a false "unchanged" leaves main's build one run behind its inputs with no
# catch-up run queued.
#
# This file is inside packages/claude-envoy, listed below, so a change to the list is itself an
# input change.
