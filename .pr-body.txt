## Summary

An agent message on an issue that is not being viewed made every Dispatch tab refetch the Inbox and pinned-issue list. The SSE client now selects cache invalidations from an exhaustive event-type switch. Adding a contract event without an explicit switch row is a TypeScript error.

`issue.updated` still refreshes the Inbox because the event carries the new issue rather than a field-level diff. It may therefore represent an assignee or priority change. `user_state.updated` now refreshes the matching user's pinned list without invalidating every issue list.

## Event-to-query table

The table covers all 40 `DispatchEvent` union members in `packages/contracts/src/dispatch-api.ts`. The Go server's `appendEvent` callers emit these names; `project.updated` is currently contract-only.

| Event type | Issue lists | Inbox | User state | Detail and related cache |
| --- | --- | --- | --- | --- |
| `project.created`, `project.updated`, `settings.repo_project.updated` | Affected project board | No | No | Projects, project detail, repository mapping |
| `settings.architecture_source.updated`, `architecture.synced`, `architecture.sync_failed` | No | No | No | Architecture source, components, architecture tree |
| `user_state.updated` | Pinned list only, for the matching user | Yes, for the matching user | Matching user's state | No issue detail |
| `issue.created` | All issue lists | No | No | Issue and event log; affected project components and architecture tree |
| `issue.updated` | All issue lists | Yes, conservatively for possible assignee or priority changes | No | Issue and event log, every issue detail for inherited parent/component changes, affected components and architecture tree |
| `issue.closed` | All issue lists | No | No | Issue and event log; affected components and architecture tree |
| `artifact.created`, `artifact.version` | No | No | No | Owner detail, artifact, issue artifact list and comments |
| `artifact.approved`, `artifact.changes_requested` | No | No. An approval answer also emits `ask.answered`. | No | Owner detail, artifact and review, owner ask list, named ask and thread |
| `ask.opened` | No | Yes | No | Owner detail, ask list and thread, anchored document, project open-ask count |
| `ask.answered`, `ask.resolved` | No | Yes | No | Owner detail, ask list and thread, anchored document, project open-ask count |
| `ask.edited` | No | Yes | No | Owner detail, ask list and thread, anchored document |
| `ask.anchor_refreshed` | No | No | No | Owner detail, ask list and thread, anchored document |
| `ask.follower_added`, `ask.follower_removed` | No | No | No | Owner detail, named ask and thread |
| `block.repaired`, `block.invalid` | No | No | No | Owner detail, issue ask list, project open-ask count |
| `comment.created` | No | Only when `ask_waiting_on` says an open ask moved | No | Owner detail, comments, anchored document, comment; its ask list and thread when it has `ask_id` |
| `comment.anchor_refreshed`, `comment.delivery`, `comment.answered`, `comment.resolved`, `comment.reopened`, `comment.edited`, `suggestion.accepted`, `suggestion.rejected` | No | No | No | Owner detail, comments, anchored document, comment and any named ask thread |
| `message.created`, `message.delivery`, `message.answered` | No | No | No | Issue detail, event log, messages, and the targeted agent conversation. An issue-less message changes only that conversation. |
| `child.status`, `child.added`, `child.removed` | No. The child issue's own lifecycle event updates lists. | No | No | Parent issue detail, event log, and children |
| `subscription.remove_requested` | No | No | No | None |
| `subscription.removed` | No | No | No | Owner detail and subscribers |

- Browser proof: the focused Chromium Playwright scenario posted an agent message on an unviewed issue while the Inbox was open. Before this change it counted `[1, 1]` requests for `[/api/v1/inbox, /api/v1/issues]`; after this change it counted `[0, 0]`. The same scenario answered an ask in a second tab and observed the original Inbox tab remove the card.
