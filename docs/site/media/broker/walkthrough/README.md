# The broker walkthrough's sources

Everything `docs/site/public/media/broker/walkthrough.mp4` is built from, and how to build it
again. These sources sit beside the scripts that record them rather than under `public/`, which
the site publishes as it is.

| Path | What it is |
| --- | --- |
| `raw/` | The footage, one file per section: four asciinema casts of the agent machine's terminal and three Playwright recordings of Dispatch, with `sections.json`: each section's wall-clock length, its marks (named on-screen events, in the file's own seconds), and how closely each browser section's last frames match its result. |
| `edl.py` | The cut: which window of which file plays, in what order, and the narration parts laid over each clip, each placed at a mark plus an offset. |
| `narration/` | One MP3 per narration part, generated by `narrate.py`. |
| `narrate.py` | Generates `narration/` through ElevenLabs. The voice and its settings are its constants. |
| `build.py` | Checks the footage and the cut, renders each clip and concatenates them into the published `walkthrough.mp4`. |

## Rebuild the video

Needs `agg` (`cargo install --git https://github.com/asciinema/agg`), `ffmpeg` and `ffprobe`.

```bash
cd docs/site/media/broker/walkthrough
python3 build.py --check   # the footage's capture rates, every mark and window inside its file, every narration part inside its clip
python3 build.py           # writes docs/site/public/media/broker/walkthrough.mp4; renders the casts once, into build/
```

`build.py` refuses footage whose length is off its section's wall clock (a browser recording
shorter than its actions or longer than its page's life, by more than 5%; a cast more than 1.5 s
shorter than its section, or longer), a clip or part naming a mark its section did not record, a
window outside its file, and a narration part that starts before its clip, overlaps the next or
runs past its clip's end. Nothing is stretched or held: a clip is its window of the file, at its
own speed, and the audio is padded with silence, never the video with frames. It prints the cut it
resolved (each clip's window in its file and where each part falls in the video), and once the
video is written it fails on dead air: 2 s or more of silence over a frozen frame (ffmpeg's
`silencedetect` and `freezedetect`, with silences a blip under 0.3 s apart counted as one).

## Change the narration

Edit the part's text in `edl.py`'s `NARRATION`, regenerate that part (or several, or all of them
when no part is named), and rebuild. `narrate.py` reads the ElevenLabs key from
`ELEVENLABS_API_KEY` in its environment, however it got there; `secrets` is one way to supply it:

```bash
ELEVENLABS_API_KEY=<key> uv run --no-project --with elevenlabs python3 narrate.py grants-revoke
secrets ELEVENLABS_API_KEY -- uv run --no-project --with elevenlabs python3 narrate.py grants-revoke
python3 build.py
```

Write a part to the clip as cut: say only what the clip shows, and keep it inside the clip's length
(`build.py --check` names a part that overruns). A part's place is its `At` in `CLIPS`: a mark in
the clip's source and an offset from it.

## Record the footage again

`bash docs/site/media/broker/walkthrough.sh` records every section into `raw/` against the demo
rig (`docs/site/media/broker/README.md`), with the rig's `DATABASE_URL`. A take records all of
them, in order: each section depends on the one before it (the browser types the code the
terminal printed, the session needs the login the browser approved, the browser approves the
request the terminal made, and the terminal records through that approval).

As it records, each section marks its on-screen events by name (`mark("code")` in
`walkthrough.record.ts`, once the login code is on screen), and `sections.json` records each mark
in its file's own seconds: a terminal mark by how long before the cast's last event (the detached
client's farewell) it was set, a browser mark by how long after the page was created, which is
where Playwright's recording starts. Since `edl.py` places everything at marks, a new take re-times
the cut itself: run `python3 build.py --check`, then `python3 build.py`, then watch the result and
adjust an offset only where the new take's pacing calls for it. A cut that should land on a moment
no mark names gets a new `mark(...)` in the recorder and a new take.

### Strategic: PASS

High confidence. A first-time approver can do it afterwards: every Dispatch page alice uses is
shown with each click and each result, and every terminal command is typed in full with its output.
Nothing is narrated that is not shown; each part was checked against its frames, as in the table
above. The live arrival of the key at 64.3 s now does the video's job, the hand-off between
terminal and browser. The setup the rig provides (the helper running, `AGENT_SECRETS_URL`, and
`AGENT_SECRETS_APPROVE_URL`, which makes the links print) is not in the video; the rest of the
Secrets Broker section is the place for it.

Nothing can be cut with no loss: every silence of 2 s or more plays over live action, the longest
being 72.5 s to 74.7 s (the Settings click, the page loading and the scroll to Live grants). The
opener repeats the result at 64.3 s on purpose, as a hook. The two long beats stay:
`session-self` (30.9 s to 37.2 s) is the only line that teaches "enrollment", the word the next
three screens use, and speech covers its static output; `approve-record` (53.6 s to 60.1 s) is the
approver's decision, with the pointer visiting each field the narration names. At 30% shorter
(about 59 s), these would go first: the opener (0 to 4.3 s), the `self` beat (31.0 s to 37.4 s,
moving "enrollment" into the request page's line), `launcher login-status` (21.2 s to 25.0 s), the
status beat (67.0 s to 72.5 s, whose `decided_by: alice` repeats the grants' Approver column), the
top of Settings (72.5 s to 74.7 s), and the Revoke line (80.3 s to the end).

The previous take's findings are closed: the Revoke line describes the pointer on Revoke; the
request page and the grants table use the word "enrollment" the `self` line taught; the key arrives
on camera; the status command's UUID typing is jumped; after Approve the pointer rests under
"Approved just now"; the Inbox shows only the credential request.
