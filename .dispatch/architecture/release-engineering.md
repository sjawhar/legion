The cross-package automation no single package owns: the router `ci.yaml`, the pull-request and main gate that selects its jobs by the paths a change touched, with the pull-request and merge-queue docs build and the pull-request worker-image build among them and `ci-ok` condensing their results into one check; the docs site's main build and GitHub Pages deploy (`docs-pages.yaml`), run on the pushes to main the router's docs filter selects, one at a time in push order; the PR-title check (`pr-title.yaml`); the release workflows (`release.yaml` for the `legion` binary and the npm plugins, `release-envoy-listener.yaml` for the Envoy listener, `release-envoy-infra.yaml` for the `envoy-infra` Pulumi plugin); and the worker-image build (`worker-image.yaml`) that publishes `ghcr.io/sjawhar/legion-worker` by digest for the Kubernetes runtime to pin. The changelog fold (`changelog-fold.yaml`) runs after each release, once a day and by hand, and folds each package's changelog fragments into its `CHANGELOG.md` on main. `.github/scripts` holds the checks those workflows run and the version-bump and release-push scripts they call, with their shell tests. Every workflow's Postgres service is the pgvector-on-PostgreSQL-18 image Envoy's `internal/testpg` pins, by the same digest, and `envoy-go` prints the server's version and pgvector's before its tests.
