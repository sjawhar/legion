The cross-package automation no single package owns: the pull-request and main gate, the PR-title check, per-package semantic-release for the TypeScript packages and the Envoy listener, the path-scoped Envoy and contracts build, and the worker-image build that publishes `ghcr.io/sjawhar/legion-worker` by digest for the Kubernetes runtime to pin. The changelog fold (`changelog-fold.yaml`) runs after each release, once a day and by hand, and folds each package's changelog fragments into its `CHANGELOG.md` on main. `.github/scripts` holds the version-bump and release-push scripts those workflows call, with their own shell test. Every workflow's Postgres service is the pgvector-on-PostgreSQL-18 image Envoy's `internal/testpg` pins, by the same digest, and `envoy-go` prints the server's version and pgvector's before its tests; the exceptions are three jobs that run on Postgres 16 for as long as production's Cloud SQL instance, which holds Dispatch's, the secrets broker's and the Legion daemon's databases, runs it: `dispatch-go-postgres-16` (Dispatch's Go suite) and `broker-go-postgres-16` (the broker's Go suite and its two-process tests) in the Envoy and contracts build, and `daemon-go-postgres-16` (the daemon's Go suite) in the pull-request and main gate. All three are removed once production runs Postgres 18.
