The Claude Code channel plugin that delivers Envoy and Dispatch traffic into Claude Code sessions. Its `dist/` bundles the envoy-client `dispatch` command, so a change there, such as `dispatch search` printing each ask hit's answer state, reaches Claude Code only with `dist/` rebuilt. It takes the session's messages from the listener's relay of the session's own durable consumer, asked for at every registration and acknowledged once Claude Code re-emitted the message (`packages/envoy/AGENTS.md`, "Session consumers"); that relay subject is the one subject it receives on, and a registration the listener can give no consumer is refused by name, which leaves the session with Envoy inbound unavailable until a later heartbeat gets one. It dials NATS with the client's shared connection options (a ping every 10 s, so a frozen path is left within 30 s), and registers as `plugin` `@sjawhar/claude-envoy` with the install's commit (the version directory Claude Code's plugin cache holds it under) as `plugin_version`, or `source` outside the plugin cache. Its session hooks add context at every session start, resume, compaction and subagent start: the session's open asks, the `dispatch-first` skill, and what people wrote to the session in the last 72 hours, read from Dispatch's `GET /api/v1/agents/{session_id}/answers` through `@legion/envoy-client/session-answers` within 800 ms of the hook's start, a subagent reading its parent's. A test runs the Claude Code release `.claude-code-pin` pins against a stand-in model and Dispatch.
