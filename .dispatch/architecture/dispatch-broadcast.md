One human's message to several live sessions at once, sent from the Agents page (`POST /api/v1/broadcasts`, human-only). A broadcast is a grouping over Dispatch's targeted messages, not a second delivery mechanism: one `broadcasts` row and one issue-less message per recipient carrying its `broadcast_id`, written in one transaction and then delivered behind the request through the ordinary targeted-message path, so each recipient's attempts, retries and replies are a single message's. A selected session that is not live, or does not advertise the chosen mode, is excluded and named in the response rather than switched to another mode; `GET /api/v1/broadcasts/{id}` reads every recipient's attempts and replies back in the order the send named them. Every send carries an `idempotency_key`, one per composed send in the dashboard, stored per human with a digest of the request in `broadcast_idempotency_keys`, so a repeat of the same send is answered the broadcast it already made rather than reaching every agent twice (LEGION-446).
