The schema every other package reads and writes through: ordered migrations applied in one transaction each at boot, the connection pools, and the session and people rows — which is why it imports `auth`. `internal/pgmigrate` holds the runner's rules, which the secrets broker's runner shares: the whole migration set is refused before anything applies when two files share a version or a file is misnamed or unreadable, and every migration's lock waits are bounded at five seconds. A process's connections are one budget of 83 (`store.ConnectionsPerProcess`), partitioned into pools sized in code so no side can starve another: requests 48, background loops 6, live-update readers 4, settlements 4, document loads 4, the health probe 1, the 3 LISTEN connections (the listener pool's one dial is one of them redialling), leases 12 (one per name on `duty`'s lease list and two spare) and the outbox 1, each pool's connections named `dispatch-<pool>` in `application_name`. Every way a guarded pool hands out a connection refuses a second one to a caller already holding one (`ErrNestedAcquire`); every acquire on every pool is bounded by an acquire tracer at its pool's bound, past which a guarded pool answers `ErrPoolBusy`; an API read runs on one pinned request-pool connection for its whole length (`PinConnection`); and a transaction commits apart from its caller's cancellation, within ten seconds. `internal/dispatch/admission` travels with the pools it is sized to: it admits each request only while the request pool has room for its class (4 read units per CPU the process may use up to 28, so 8 on two CPUs; 8 write units; a queue as long as the limit and at most 75 ms of waiting), refuses the rest at once with `429 OVERLOADED` and `Retry-After`, and answers a busy pool or a read past its deadline with a retryable `503 DATABASE_BUSY` or `503 REQUEST_TIMEOUT`.
