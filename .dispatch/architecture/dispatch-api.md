Every HTTP route body: issues, artifacts, asks, comments, messages, projects, and the assignee, rank, label and component-attachment writes. The largest package in the server (87 files) and the one every Dispatch feature touches. It resolves an agent's actor through the listener's OIDC and routing packages, hence the edge to `envoy-listener`. The edge to `contracts` is the wire contract rather than a Go import: `contracts/src/dispatch-api.ts` declares the response shapes these handlers produce and the web app consumes, and code generation covers only the event envelope, so there is no Go type to import.

A write route's transaction runs in two phases. Its read phase holds no transaction id: it takes the owner's advisory lock as its first statement (`requireOpenOwner[Status]`, `requireOpenIssue`, `lockIssueRows`, through `store.LockOwner` and `LockOwners`), reads what the write decides on in the statements after that lock - never in the lock's own statement, whose READ COMMITTED snapshot is taken before the wait and would miss a close committed meanwhile - and does all its document work through `Docs.Join` and its write advice (`writeAdvice`, which counts the counted event the write is about to append). Its writes are queued on the ledger in the order it makes them (`api/write_queue.go`: `queueWrite`, `queueExec`, `queueEvent`, `queueStamp`, `queueReferences`), with what a later step or the response needs passed through captured values, and `ledger.Commit` runs them back to back as the write phase, returning a failed step's error unchanged so the route answers what it answers for that error. A route with no document work (issue patch, message create, claim) reads and advises before its first write and keeps its writes inline, as does a write whose result steers the route (issue create's `update projects` and external-link insert). `putThreadRead` takes the owner's lock in shared mode, so a thread read waits for a writer in its read phase rather than race that writer's trigger. The read phase still holds its pooled connection, idle in transaction.
