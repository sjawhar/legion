Every HTTP route body: issues, artifacts, asks, comments, messages, projects, search, and the assignee, rank, label and component-attachment writes, and the per-session list of what people wrote to an agent (`GET /api/v1/agents/{session_id}/answers`, `session_answers.go`), which every agent host reads on each model request. Search reads each ask hit's answer state from its row, and a resolved ask's last answer from its `ask.answered` events, before it answers. The per-session list's read model is the small package `sessionanswers` (`List`), which travels with its one route: a person's events whose `published_destinations` hold the session's own topic (`contracts.AgentSubject`), its sent message and comment deliveries, each item at its current words as a `model.SessionAnswer` with its relation to the session and its `dispatch://` and deep-link place; the outbox's tests read back through it, so the route reads what the publisher records. The largest package in the server (99 files besides its tests) and the one every Dispatch feature touches. It resolves an agent's actor through the listener's OIDC and routing packages, hence the edge to `envoy-listener`. The edge to `contracts` is the wire contract rather than a Go import: `contracts/src/dispatch-api.ts` declares the response shapes these handlers produce and the web app consumes, and code generation covers only the event envelope, so there is no Go type to import. It also runs the related-item check every issue create, ask and new decision block gets once its write commits (a search by the text's rarest words and by meaning, waited on for at most 5 s and recorded in `related_checks`), the no-write route and the records route over it, and the term-statistics refresh its keyword picker reads. `Register` serves each row of the route table admitted (`admission`), a read under a 20-second deadline (five minutes for a file version download) and on one pinned request-pool connection, a write with no deadline; a refused request's body is drained before its `429`. Every handler that writes a live document takes that document's writer gate before it opens its transaction (`document_writers.go`), so writers queued on a busy document hold no connection. The event stream relay and the delivery hub read through the live pool, and a route that reads side by side runs at most two reads at once.
