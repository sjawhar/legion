Stages 1 and 2 on `main` provide Postgres migrations and boot history (`internal/store`), the local daemon registry, durable role claims, and pending task delivery (`internal/registry`). Stage 3 (LEGION-219) plans the per-issue record, admission slots, phase and gate facts, transactional outbox, and `internal/projection`; the coordinator never mirrors Dispatch or GitHub.

The issue record keeps each tree's memory group on the tree's root: migration `20261104073148_issue_memory_group` adds `memory_group` (`memory` or `none`), `memory_draw_mode` (the project's `projects.<KEY>.memory.mode` in force at the draw) and `memory_drawn_at` to `issues`, and backfills no row. `memory_drawn_at` is the draw itself, null exactly while none is recorded, which is what makes the three write-once: `record.Store.DrawMemory` writes only where it is null, `CarryMemory` writes only onto a row that has none, and `PutIssue` names none of them, so a copy of the record read before the draw never writes it back and a re-admission, a new generation and `ClearTreeGeneration` keep what was drawn. A row written before the migration therefore carries no draw, which is a tree with no group that runs without memory and is drawn for by nothing later. Migration `20261104153554_issue_memory_carried` adds `memory_carried` beside the three: `CarryMemory` writes it on a root handed over out of another tree, where it says the hand-over settled that root's memory — its old tree's draw where that tree had one, and no draw where it had none — and `DrawMemory` writes nothing for a root it is set on, so the child's answer is the one its hand-over wrote and not a later read of the old tree. That migration also settles the hand-overs the release before it recorded, by `CarryMemory`'s own rule: a row whose `handed_over_from` names a tree holding a `tree_lifecycles` row of the project's normalized token, and that carries no draw of its own, is marked carried and takes no group, those old trees having run before memory existed. `issueColumns`, `scanIssue`, `PutIssue` and `record.Issue` name it nowhere: apart from that backfill, `CarryMemory` is its only writer and `DrawMemory` its only reader.
