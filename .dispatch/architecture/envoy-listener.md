Ingests GitHub, Slack and Ghost Wispr webhooks, publishes ordinary notifications through JetStream, and role lanes and ad-hoc `notifications.` topics the stream does not capture through core NATS, resolves live sessions and delivers by `prompt_async`; tracks PR check settlement. The `ENVOY_NOTIFICATIONS` stream and each KV bucket hold the deployment's replica count (`ENVOY_NATS_REPLICAS`), and the stream has a byte limit (`ENVOY_STREAM_MAX_BYTES`) past which it refuses new publishes (`DiscardNew`, a retryable `bus.ErrStreamFull` the webhook answers 503) and keeps every stored message until its 72-hour age; a clustered server's duplicate acknowledgement with no sequence, for a retry of a refused message, is the retryable `bus.ErrNotStored`, never a success. A start raises a stream or bucket found with fewer copies, and a stream with a smaller byte limit or none, never lowers either, and keeps the stream's metadata, `envoy_stream_id` included, and its other limits on every update. JetStream's stream update has no compare-and-swap, so a concurrent start with other or no settings can put back the copies, limit and metadata it read; every owning program (the listener, Dispatch's server) therefore runs a keeper that every 30 seconds raises the stream's copies and byte limit back to its settings, puts back the discard policy and `envoy_stream_id`, and raises its own buckets' copies. An operator's raise of the limit stands, and the stream holds the most copies and the largest limit any program of a deployment carries. The small packages that instrument that path belong to it rather than to components of their own: OpenID Connect token verification for service accounts and the authorization code flow Dispatch's sign-in runs (`oidc`), the signature and duplicate-delivery guards (`verify`, `dedupe`), `metrics`, `id`, `logging`, listener bootstrap (`config`), the `natstail` diagnostic tail, and the listener's own harnesses (`integration`, `smoke`, `testnats`). `internal/dispatch/config` sits under the Dispatch tree but belongs here: it loads the shared `envoy.json` shape — NATS URLs, the Dispatch server URL and token — that `natstail`, the Dispatch server and the Envoy plugin all read.
