The composition root of the native Dispatch API: `cmd/dispatch` reads its boot configuration from the environment and assembles the server, and `internal/dispatch/routes` is the route table and the router wiring every handler package together. Each subsystem it composes is a child component below. Its wire types match the language-neutral contracts, which is a compatibility rule rather than a Go source dependency, so no edge is drawn for it. It hands the background loops the background pool and the leased loops the lease pool, so no loop waits for a request's connection nor a request for a loop's, and it makes the one admission limiter the API admits through. Logging never blocks a caller: `internal/dispatch/logging` formats each line in its caller and hands it to one writer goroutine through a bounded buffer, dropping and counting what does not fit, and every exit writes what is still buffered. With `DISPATCH_METRICS_ADDR` set it serves Prometheus `/metrics` (per-pool connections and acquire waits, admission, the writer gates, settlements, the outbox's lag and publishes, events committed, the Go runtime, dropped log lines) on the repository's own `internal/metrics`; with `DISPATCH_PPROF_PORT` set the profiler records mutex and block profiles too. Shutdown runs every stage inside one deadline, `stopGrace` less three seconds, made at the signal.

Beside the suggestion-outcome sweep, `cmd/dispatch` starts the term-statistics refresh the related-item check picks its keywords from, at boot and every ten minutes, on the background pool.
