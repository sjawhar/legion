The Oh My Pi plugin every session loads (`@sjawhar/pi-envoy`): Envoy subscriptions and delivery, the `dispatch` command on every shell's `PATH`, the per-request context (the `dispatch-first` skill at the head of every model request, and at the tail of each main-loop request, never of a side turn, the handoff prompt or a remote compaction's request, what people wrote to the session in the last 72 hours, read from Dispatch's `GET /api/v1/agents/{session_id}/answers` through `@legion/envoy-client/session-answers`, a subagent reading its parent's), and the five skills every session with Dispatch reads (the Dispatch and Envoy skills, and `asd-ste100`). It publishes the in-process interface in `pi-shared` that the Legion plugin claims its roles through. It dials NATS with the client's shared connection options (a ping every 10 s, so a frozen path is left within 30 s), runs the catch-up of missed messages (`POST /v1/replay`) on each reconnect, and registers as `plugin` `@sjawhar/pi-envoy` with its package version as `plugin_version`.

The plugin's two serial task queues, each task's deadline and fence, and the registration and role state those tasks write live in one module, `packages/pi-envoy/src/registration-state.ts`. The extension entry declares none of it. A queued task acts through a handle that refuses every step — a state write, a listener request, a NATS subscribe or the acquisition of the NATS connection — past that task's deadline, or once its session is no longer the open session, and the first refusal latches. The module also mints this extension instance's client instance id and sends it on every registration and on the shutdown deregistration. That id is what lets the listener tell this instance's own predecessor from another process's live session: a soft claim naming a predecessor takes the role only when that predecessor has no live registry entry, when its live entry carries this instance's id, or when either side carries no instance id. A refused session keeps running and stays registered, without the role.
