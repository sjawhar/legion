# How a role claim lives

Read this when a role you held is gone after a resume, fork or restart, when `envoy_role_set` is refused, or when a role publish returns `no holder`.

- A claim belongs to the session, not the process. `omp --resume` re-claims the role recorded in the session transcript, also after the reaper removed the old session's row (the reaper removes a row only once that session is `gone`: past the gone horizon, `ENVOY_SESSION_GONE_HORIZON`, 1h by default).
- `/fork`, `/branch`, `/handoff` and any other switch that carries the transcript read the role the previous session id held and move it to the new id while the new session starts. `/new` and `/resume` install an unrelated transcript and carry nothing.
- A holder that has not registered for longer than the live window (`ENVOY_SESSION_LIVE_WINDOW`, 5m by default) reads `unresponsive`, and keeps its role: role publishes return an error that names the holder, its `holder_state` and its `last_seen`, and says it did not confirm the message (`receipt_timeout`). Nothing in that path releases the claim. Only the reaper does, once the holder is `gone`; publishes return `no holder` from then until that transcript resumes or another session claims the role.
- An automatic reclaim never steals. It is a soft claim, which the listener grants only when the role is unheld, held by a session that is `gone`, held by the id this session continues (a fork's parent), or — on a Legion role — held by a session that is `unresponsive`, which is how a relaunched Legion role recovers it after the live window. When a `live` session holds it (the parent of a `/fork` whose role moved to the child, or a second process on the same transcript), the listener refuses atomically, and the resumed session logs a warning and holds nothing.
- Only an explicit `envoy_role_set` is last-claim-wins. Running it again for a role this session already holds is harmless.
- If another plugin made subscriptions that depend on your current role, `envoy_role_set` to a different role is refused, and the refusal names those subscriptions. `envoy_unsubscribe` keeps those subscriptions and lists them as kept.
